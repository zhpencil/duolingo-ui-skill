# Duolingo UI — 页面布局

这份文档把 16 个 Figma 流程界面逐个拆开，再补上 Marvilo 文件里的排行榜 / 商店 / 资料页和 `demo.html` 的 4 台可操作手机。每个界面都给出纵向结构、关键尺寸、用到的类和交互。先看线框，再看数字，最后照 `assets/demo.html` 写。

画板统一 **430×932**，内容左右 **16px**。下面的高度是“这一段占多少”，不是 CSS 固定高；页面本身由内容撑开，只有顶栏、底栏、行动区是固定高度。

```
│ └──────────────────────────┘ │
│            ★                 │ 路径：22 上 / 24 左右 / 18 行距
│         ⬤  🧍                │  金色里程碑 / 角色
│            ⬤                 │
│         ⬤ START              │  当前节点 + 白 START 气泡
│            ⬤                 │

│           ▬▬▬▬▬              │ 34  home indicator
└──────────────────────────────┘
```

纵向结构：

| 区域 | 高度 | 说明 |
|---|---|---|
| 顶栏 | 54 | 4 个计数：连胜、宝石、能量、红心；左右 16 |
| 章节头 | 最小 75 | margin 0 16；紫面 + 4px 深紫底边；右侧 54px 按钮列 |
| 路径 | 内容撑开 | 上 22 / 左右 24 / 下 30；节点行距 18；`--duo-path-x` 左右错开 |
| 底部导航 | 94 | 5 个 40×40 目标，图标 32 |
| Home indicator | 34 | 148×5 黑条 |

用到的类：`.duo-appbar`、`.duo-counter`、`.duo-section-header`、`.duo-path`、`.duo-path__row`、`.duo-node`、`.duo-start`、`.duo-path__stars`、`.duo-bottom-nav`。

路径的节奏：金色里程碑 → 角色 → 紫色课程节点 → 当前节点（白环 + START）→ 后续节点 → 宝箱 → 底部角色。节点不是等距直线，每 3–4 个用 `--duo-path-x` 偏移 40–80px，形成 S 形。角色插画站在节点旁边，底部对齐，占 90–120px 宽；不要让它挡住节点。

交互：节点可点，按下下沉 4px；当前节点上方 8px 放 `.duo-start`；点击 START 进入答题。路径滚动时顶栏和底栏固定。

## 03 · 路径 + 单元卡

02 的滚动状态：当前节点被滚到屏幕下方，底部升起一张紫色单元卡（圆角 20，白色标题 + “Lesson 2 of 5” + 白色 START 按钮）。它的作用是把“这个节点学什么”说清楚。

卡片宽度 = 屏宽 - 32，底部留 16；标题 22/800 白，副标题 16 `#edd1ff`；按钮白面 + 淡紫边 + 紫字，高 48。卡片出现时路径其余部分压到 40% 黑遮罩，卡片本身不遮。不要把它做成白色对话框。

## 05 · 答题（已拼好 + 结果）

```
┌──────────────────────────────┐
│ ✕  ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬     ❤️5  │
│ Translate this sentence      │
│ 角色 + 气泡                   │
│ ┌ We ┐┌ are ┐┌ men ┐         │ 答题行：词块 / 蓝字
│ ──────────────────────────── │
│ ──────────────────────────── │
│   ten  [空]  sorry  four     │ 词池：原词留下空槽
│      [空]  are  always       │
│ ┌──────────────────────────┐ │
│ │ ✓ Nice!              ⤴ 🚩 │ │ 淡绿结果面板
│ │        CONTINUE          │ │ 绿色 48 + 5
│ └──────────────────────────┘ │
│           ▬▬▬▬▬              │
└──────────────────────────────┘
```

- 上屏的词：`.duo-word--placed`。默认是 **蓝色 20/700 文字**（与线上 App 一致）；如果要求 1:1 复刻 File 1 的截图，给答题行加 `.duo-answer-line--chips`，上屏词就变成和白词卡一样的 46px 白底 chip。两种都不要让原词留在词池里可见。
- 词池里的原词加 `.duo-word--used`（透明、不占点击），但**保留占位**，所以 “ten / sorry / four / are / always” 的位置不会重排。
- 结果面板 `.duo-result`：整宽、淡绿 `#d6ffb8`、标题 24/800 `#58a700`、右侧分享 / 举报图标、底部绿色 CONTINUE。错误版换成 `.duo-result--error`（淡红、`#d33131`）。
- 结果面板从底部出现，页面内容上移；它不是 Toast，也不悬浮在 CHECK 上方。demo 里用 Toast 只是为了演示 `Duo.toast()`，真正的答题反馈请用 `.duo-result`。

## 页面组装的通用顺序

1. 先定**这一屏的主行动**是什么：学习（绿）、继续（蓝）、领取（蓝）、危险（红）。一屏只能有一个。
2. 再定**有没有顶栏 / 底栏**：首页有 54 + 94；课程只有 54 课程栏；奖励页两者都没有，只留 home indicator。
3. 再排**信息带**：章节头 75 → 路径；标题 26 → 题目；资料头 278 → 统计。
4. 最后加**浮层**：sheet / dialog / toast。浮层永远在内容之后、`.duo-phone` 之内（或 body 末尾，固定定位）。

按这个顺序写，页面不会出现“所有东西都挤在中间”的问题。
